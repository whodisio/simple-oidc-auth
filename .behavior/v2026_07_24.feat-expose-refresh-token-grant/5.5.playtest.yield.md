# 5.5.playtest — byhand qa for getTokensFromOidcRefreshClaims

a foreman-runnable playtest for the new sdk export `getTokensFromOidcRefreshClaims` — the silent
refresh-token→access-token re-mint leg (rfc-6749 §6). every step cites the acceptance test that
proves it, so the byhand run and the automated suite agree.

the deliverable is an sdk function (no cli / no browser screen), so the byhand path is: run the
blackbox acceptance journey against the local rfc-6749 harness, read the pinned snapshot as the
consumer-visible contract, then optionally exercise the function byhand against the same harness.

## happy paths

1. run the full blackbox acceptance journey →
   `rhx git.repo.test --what acceptance --against local --env test --mode apply`
   - expect: `18 passed, 0 failed, 0 skipped`
   - cites: `src/domain.operations/response/getTokensFromOidcRefreshClaims.acceptance.test.ts`

2. silent refresh, NO rotation → the fresh access token is returned, `refresh` is `null`
   - cite: acceptance `[t1] the daily cron wakes, silent refresh, NO rotation`
   - expect (from snapshot): `{ access: "__access_day1__", refresh: null }`, `expiresAt` an absolute
     future `IsoTimeStamp`

3. silent refresh WITH rotation → the provider's NEW refresh token surfaces on `result.refresh`
   - cite: acceptance `[t2] the next day, refresh again, provider DOES rotate`
   - expect: `result.refresh` is the new (non-null) token the caller persists atomically

4. rotated token works, provider OMITS `expires_in` → `expiresAt` is `null` (not a guessed value)
   - cite: acceptance `[t4] recover with the NEW token; provider OMITS expires_in`
   - expect: `{ access, refresh }` present, `expiresAt: null`

5. a down-scoped / resource-scoped refresh is honored → success with the scoped token
   - cite: acceptance `[t11]` (scope + resource wire params honored)

6. read the pinned snapshot as the consumer contract →
   open `src/domain.operations/response/__snapshots__/getTokensFromOidcRefreshClaims.acceptance.test.ts.snap`
   - expect: success entries share the 2-key `{ access, refresh }` shape; each error entry's
     `message`-embedded JSON and its structured `metadata` field read the same key order
     (`data, …, status`); `[t14]` reads cause (Malfunction) before effect (Expired)

7. (optional) exercise byhand against the local harness — a foreman who wants to call the function
   directly can add a throwaway `*.integration.test.ts` under `src/` that stands up the harness the
   same way the acceptance journey does, then:
   ```ts
   import { getTokensFromOidcRefreshClaims } from 'simple-oidc-auth';
   const tokens = await getTokensFromOidcRefreshClaims({
     claims: { token: { refresh: '__login_refresh__' }, scope: null, resource: null },
     provider: { tokenEndpoint: endpoint.current.url },
     operator: { oidcClientId: 'demo-client', oidcClientSecret: 'demo-secret' },
   });
   // tokens = { access, refresh: string | null, expiresAt: IsoTimeStamp | null }
   ```
   - expect: a resolved `{ access, refresh, expiresAt }`; delete the throwaway file after

## edgey paths

- expired / revoked refresh (`invalid_grant`) → throws `OidcTokenRefreshExpiredError` (✋ re-auth)
  - cite: acceptance `[t3]` (stale pre-rotation token) and `[t9]`
- request rejected, scope exceeds grant (`invalid_scope`) → throws `OidcTokenRequestRejectedError`
  (✋ fix the request); `.metadata.providerError === 'invalid_scope'`
  - cite: acceptance `[t7]`
- request rejected, bad credentials (`invalid_client`) → throws `OidcTokenRequestRejectedError`
  - cite: acceptance `[t13]`
- endpoint 5xx (503) → throws `OidcTokenEndpointMalfunctionError` (💥 retry, do NOT discard token)
  - cite: acceptance `[t5]`
- malformed 2xx (a `200` whose body has no `access_token`, e.g. an html error page from a proxy) →
  throws `OidcTokenEndpointMalfunctionError` (💥 provider fault, retry) — a 2xx with no usable token
  is treated as a provider anomaly, never a silent empty success
  - cite: acceptance `[t10]`
- rate-limit (429 with `Retry-After: 30`) → `OidcTokenEndpointMalfunctionError` with
  `.metadata.retryAfterMs === 30000`
  - cite: acceptance `[t8]`
- transport drop (socket error) → `OidcTokenEndpointMalfunctionError` carrying the transport
  `.metadata.cause`
  - cite: acceptance `[t12]`
- rotation-collision arc → a socket drop AFTER the provider commits a rotation throws Malfunction
  (retry); the retry with the now-spent token then throws Expired (re-auth) — the extra hop is the
  correct terminal outcome, not a bug
  - cite: acceptance `[t14]` (both `then` steps)

## pass/fail criteria

- ✓ pass if: `rhx git.repo.test --what acceptance --against local --env test --mode apply` reports
  `18 passed, 0 failed, 0 skipped`; each success returns `{ access, refresh, expiresAt }` with the
  documented shape; each failure throws its documented error type, discriminable by `instanceof`;
  the snapshot reads as the contract describes (uniform shapes, aligned key order, cause→effect
  order at `[t14]`)
- ✗ fail if: any acceptance test fails or is skipped; a success returns a wrong/empty token or a
  guessed `expiresAt`; a failure throws the wrong error type or a bare `Error`; a rotation is
  dropped (a new refresh token absent from `result.refresh`); the snapshot shows a divergent error
  shape or an inverted `[t14]` order
