# 3.3.1.blueprint.product — getTokensFromOidcRefreshClaims

## summary

build the refresh-grant twin of `getTokensFromOidcResponseClaims`. a public orchestrator
`getTokensFromOidcRefreshClaims` accepts `{ claims, provider, operator }`, delegates to a new http
communicator `exchangeRefreshTokenForTokens`, and returns `{ access, refresh, expiresAt }`.
the communicator composes two pure transformers — `asOidcTokenError` (classify a rejection
into one of three typed errors) and `asExpiresAt` (convert `expires_in` → absolute
`IsoTimeStamp`). three new error classes over the `helpful-errors` bases give the caller an
`instanceof` discrimination between re-auth / fix-request / retry. a new `OidcRefreshClaims`
domain object names the unverified assertion bundle (`token.refresh`, `scope`, `resource`).

decomposition follows the repo's grain split (orchestrator → communicator → transformers) and
the extant `{ claims, provider, operator }` contract shape. one net-new dependency: `iso-time`.

## codepath tree

```
getTokensFromOidcRefreshClaims(input: { claims, provider, operator })      [+] orchestrator (public)
│   .what = convert the claims-bundle into wire scalars (via transformer), delegate to the leaf, return result
│
├─ input.claims: OidcRefreshClaims                                    [+] domain.object (PUBLIC contract only)
│    { token: { refresh }, scope: string[]|null, resource: string|null }
│
├─ asOidcRefreshWireParams({ claims })                                [+] transformer (pure)
│    .what = unpack the OidcRefreshClaims bundle → flat wire scalars { refreshToken, scope, resource }
│    ├─ refreshToken = claims.token.refresh
│    ├─ scope    = claims.scope space-delimited join (rfc-6749 §3.3); undefined when null or [] (inherit full grant)
│    └─ resource = claims.resource verbatim (rfc-8707 absolute uri); undefined when null (no audience restriction)
│    .note = `[]` maps to undefined (inherit full grant), the SAME as null — this is the DECLARED
│            boundary in 2.1.criteria.blackbox (boundary table: "scope = [] (empty) treated as null").
│            rationale: rfc-6749 §6 has no "zero scopes" request — an empty scope param is not a
│            narrower grant, it is the absence of a scope assertion. so `[]` and null are one intent
│            ("no scope opinion"), collapsed deliberately, not a silent surprise.
│    .why = the join + null/[]→undefined coalesce is decode-friction; a named transformer keeps the
│           orchestrator a narrative of named calls only (rule.forbid.inline-decode-friction)
│
└─ exchangeRefreshTokenForTokens({ endpoint, oidcClientId, oidcClientSecret, refreshToken, scope, resource })  [+] communicator (i/o leaf)
   │   .what = POST the refresh grant with WIRE SCALARS ONLY; classify failures; map success
   │   .note = takes flat scalars, NOT the OidcRefreshClaims domain object — mirrors the extant peer
   │           exchangeOidcResponseCodeForTokens (flat scalars), keeps the leaf a pure wire boundary
   │           that a unit test drives with no domain object to build
   │
   ├─ axios POST (grant_type=refresh_token, refresh_token, client_id, client_secret, scope?, resource?)  [←] reuse axios idiom
   │    client_id + client_secret sent in the body (rfc-6749 §2.3.1 MAY; mirrors the code-grant leaf, lines 36-37)
   │    scope + resource are already-serialized scalars (or omitted when undefined)
   │    validateStatus: () => true                                    [←] reuse from code-grant leaf
   │
   ├─ (transport throw: ECONNREFUSED/timeout)                         [+] catch → throw OidcTokenEndpointMalfunctionError
   │
   ├─ asOidcTokenError({ status, data, headers })                     [+] transformer (pure)
   │    .what = pick the typed error for a non-2xx / error-body response
   │    defensive read: error-code = (typeof data === 'object' && data) ? data.error : undefined
   │       — a non-JSON / malformed body (html proxy page, empty 503) yields undefined, NOT a raw
   │         TypeError; an undefined code on a 4xx routes to the Rejected default (fix-request)
   │    named status bands (rule.forbid.magic-values): HTTP_SERVER_MIN = 500, HTTP_TOO_MANY = 429
   │    classify by STATUS BAND first, then refine 4xx by error code:
   │    ├─ status >= HTTP_SERVER_MIN    → OidcTokenEndpointMalfunctionError [+] (MalfunctionError 💥) retry
   │    ├─ status === HTTP_TOO_MANY     → OidcTokenEndpointMalfunctionError [+] (💥) retry-with-backoff
   │    │     (rate-limit is transient + retryable, like a 5xx — NOT a request to fix)
   │    │     .honor Retry-After: retryAfterMs = parse(headers['retry-after']) delta-seconds→ms
   │    │       defensive: only a well-formed non-negative integer yields a number; a NaN /
   │    │       negative / http-date form (rfc-7231 allows a date, unhandled here) → undefined,
   │    │       never a NaN leak (upholds the "absent → undefined" contract)
   │    │       carried on the error metadata so the caller backs off the provider-named interval
   │    ├─ 4xx + error=invalid_grant    → OidcTokenRefreshExpiredError    [+] (ConstraintError ✋) re-auth
   │    ├─ 4xx + any other/absent error → OidcTokenRequestRejectedError   [+] (ConstraintError ✋) fix-request
   │    │     (covers invalid_scope, invalid_request, invalid_client, and an unrecognized 4xx)
   │    └─ 2xx + malformed body (no access_token) → OidcTokenEndpointMalfunctionError [+] (💥) retry
   │
   │    rationale: a 4xx is a caller-fault by http semantics, so an unrecognized 4xx defaults to
   │    "fix the request" (non-retryable) — NOT malfunction — so a caller never loops-retries a
   │    request the provider will keep refusing. the ONE retryable 4xx is 429 (rate limit), pulled
   │    out ahead of the generic-4xx default. only 5xx + 429 + broken-2xx are server/transient (retry).
   │
   ├─ asExpiresAt({ expiresIn, since })                               [+] transformer (pure)
   │    .what = expires_in (s) + reference instant → IsoTimeStamp | null
   │    └─ addDuration(since, { seconds: expiresIn })                 [←] reuse iso-time
   │
   └─ success-body map (2xx) — extract from response.data:
        ├─ access_token  → access   (required; absent → asOidcTokenError malformed-body → Malfunction)
        ├─ refresh_token → refresh  (null when the field is absent — no rotation)
        └─ expires_in    → asExpiresAt({ expiresIn: expires_in, since: now() }) → expiresAt (null when absent)

return { access: string, refresh: string | null, expiresAt: IsoTimeStamp | null }
```

**grain rationale (why this decomposition):**
- **orchestrator** (`getTokensFromOidcRefreshClaims`) — the public contract; a narrative of named
  calls only. it converts the `OidcRefreshClaims` bundle into wire scalars via the
  `asOidcRefreshWireParams` transformer, delegates to the leaf, returns its result. no inline
  decode-friction (rule.forbid.inline-decode-friction). the domain object lives ONLY at this
  public boundary.
- **communicator** (`exchangeRefreshTokenForTokens`) — the sole i/o boundary; takes flat wire
  scalars (never the domain object), owns axios, the transport-error catch, and the two transformers.
  mirrors the extant peer `exchangeOidcResponseCodeForTokens`, which also takes flat scalars.
- **transformers** (`asOidcRefreshWireParams`, `asOidcTokenError`, `asExpiresAt`) — pure, no i/o,
  unit-testable without mocks. extracted precisely because the claims-unpack (scope join +
  null/[]→undefined coalesce), the error-classification, and the `now()+x` conversion are
  decode-friction that would otherwise clutter the orchestrator or communicator
  (`rule.require.named-transformers`).

**purity note:** `asExpiresAt` takes `since` as an argument (the reference instant) rather than
call `now()` itself — this keeps it a **pure** transformer. the communicator reads `now()` once
and passes it in, so the impurity sits at the i/o boundary where it belongs.

## domain object contract — `OidcRefreshClaims`

```ts
export interface OidcRefreshClaims {
  /** the token claim — "this refresh token is valid & belongs to this operator" */
  token: { refresh: string };
  /** the scope claim — grains of access to mint; subset of original grant; null = inherit all */
  scope: string[] | null;
  /** the resource claim (rfc-8707) — target audience uri; null = no audience restriction */
  resource: string | null;
}
```

- a plain `interface` (not a `domain-objects` class) — it carries no identity/lifecycle, mirrors
  how `OidcResponseClaims` is declared (a plain interface). all three keys present; `scope`/
  `resource` nullable, never optional (`rule.forbid.undefined-attributes`).
- **scope boundary**: this domain object is the PUBLIC orchestrator input ONLY. the orchestrator
  converts it into wire scalars via `asOidcRefreshWireParams` before it calls the communicator, so
  the i/o leaf never sees a domain object (it takes flat `refreshToken` / `scope` / `resource`
  scalars, like the extant peer `exchangeOidcResponseCodeForTokens`). the domain concept stays at
  the public boundary; the wire boundary stays primitive.

## error contracts — the triad

each class carries a **pinned `.message`** (so the acceptance snapshot locks a designed string,
not an accident of the first run — `rule.require.failloud`) plus structured metadata. the two
caller-fault classes share the same `{ status, data }` metadata slice; the server-fault class
widens it with `cause` (transport error) and `retryAfterMs` (parsed from the 429 `Retry-After`
header), so the caller backs off for the provider-named interval instead of a blind guess.

```ts
// errors/OidcTokenErrorMeta.ts — the shared metadata slice, its OWN file so no error
// class arbitrarily "owns" it among coequal siblings; all three import it (one declaration, no drift)
export interface OidcTokenErrorMeta { status: number; data: unknown }

// caller-fault ✋ → re-auth
export class OidcTokenRefreshExpiredError extends ConstraintError {
  // message: 'refresh token expired/revoked — re-authenticate'
  // metadata: OidcTokenErrorMeta
}
// caller-fault ✋ → fix the request
export class OidcTokenRequestRejectedError extends ConstraintError {
  // message: `refresh request rejected: ${providerError ?? 'unrecognized'} — fix the request (scope/credentials), do not retry as-is`
  // metadata: OidcTokenErrorMeta
  // note: the `?? 'unrecognized'` fallback ensures a malformed 4xx with no `error` key never
  //       renders the literal string "undefined" in the message (a failloud violation)
}
// server-fault 💥 → retry
export class OidcTokenEndpointMalfunctionError extends MalfunctionError {
  // message: 'token endpoint malfunction — retry with backoff'
  // metadata: OidcTokenErrorMeta partial + { cause?: Error; retryAfterMs?: number }
}
```

- **pinned messages** — the templates above are the design of record; the acceptance test
  snapshots them, so a drift is caught in review rather than silently re-baselined. the
  `${providerError}` slot in the Rejected message interpolates the provider's `error` code
  (`invalid_scope` / `invalid_request` / `invalid_client`) so the fix is named, not vague — with a
  `?? 'unrecognized'` fallback so an absent `error` key never renders the literal `"undefined"`.
- **shared metadata slice** — both caller-fault classes carry `OidcTokenErrorMeta` (one type,
  no independent redeclaration → no drift between the three); the Malfunction class widens it
  with `cause?` (transport) and `retryAfterMs?` (rate-limit backoff hint).
- **`retryAfterMs` wires the "honor Retry-After" promise** — on a 429, `asOidcTokenError` parses
  the `Retry-After` header (delta-seconds → ms; absent → `undefined`) onto the error, so the
  discrimination guarantee extends to *how long* to wait, not merely *that* a retry is due.
- each carries `{ status, data }` so a debugger sees the exact provider signal — the `Expired`
  caveat (invalid_grant covers revoked/wrong-client too) is served by the metadata.

### snapshots

for an sdk library, the **contract stdout** is the public export's return object + each thrown
error (there is no cli/api stream). the exhaustive contract snapshots live in the **acceptance
test** (`getTokensFromOidcRefreshClaims.acceptance.test.ts`) — it imports the SYMBOL from the built
package entrypoint (blackbox, exactly as a consumer does) and drives it against the local
RFC-6749 endpoint, so the snapshot proves the *shipped* surface, not a source-internal path.
snapshot exhaustively (positive + every negative), via the repo's `toMatchSnapshot()` idiom:

- ✅ success result **stable fields** `{ access, refresh }` — rotation present (`[t2]`) + absent (`[t1]`) (positive)
- ✅ `OidcTokenRefreshExpiredError` message + metadata shape (invalid_grant → re-auth; `[t3]` stale + `[t9]` revoked)
- ✅ `OidcTokenRequestRejectedError` message + metadata shape (invalid_scope → fix-request; `[t7]`)
- ✅ `OidcTokenEndpointMalfunctionError` message + metadata shape (503 `[t5]` + 429-with-`retryAfterMs` `[t8]` → retry)
- ✅ `expiresAt: null` shape when the provider omits `expires_in` — exercised at `[t4]` (edge)

**deterministic-`expiresAt` strategy (so the acceptance snapshot passes on every run):** on a
success with `expires_in` present (`[t1]`/`[t2]`), `expiresAt = addDuration(now(), { seconds })`
is a wall-clock value that would change per run — so it is **excluded from the snapshot** and
asserted separately: the snapshot captures the stable `{ access, refresh }` shape, and a
paired `then` range-asserts `expiresAt` is an `IsoTimeStamp` within a tolerance window of
`now() + expires_in` (e.g. ±5s). the `expiresAt: null` case (`[t4]`) has no clock component, so
it stays a full-object snapshot. this keeps the blackbox tier hermetic without a clock injected
into the built package (the `since` param of `asExpiresAt` is not reachable through the public
export, so a range-assert is the blackbox-appropriate mechanism, not clock injection).

the **unit** test additionally snapshots the axios request payload (wire params) via
`axiosMock.mock.calls` — that is a mechanism snapshot (the request we send), distinct from the
contract snapshots above (the values a consumer receives).

### the local token-endpoint harness (`genLocalRfc6749TokenEndpoint`)

the single biggest net-new test-infra piece (no repo precedent; `[→] replace` the `.skip`-ped
real-provider approach). a small in-process node `http` server that:

- accepts `POST` form-urlencoded, asserts `grant_type=refresh_token` + `refresh_token`
- answers whatever the **currently-set response** dictates (see the reconfiguration contract below)
- returns its `tokenEndpoint` url (`http://127.0.0.1:<port>/token`) for the test to pass as
  `provider.tokenEndpoint`
- torn down in `afterAll` (real i/o, no mocks — honors `rule.forbid.integration.mocks`)
- **shared by both the integration and acceptance tiers** — the integration test imports it
  from source; the acceptance test also stands up the same local endpoint, so no external
  provider or credential is needed to run acceptance (the built package is exercised against a
  real-but-local http server, honoring `rule.forbid.acceptance.mocks`).

**the reconfiguration contract** — the harness is one shared instance walked through the journey's
sequential timesteps (`--runInBand`), so its next answer must be settable between awaited calls.
`genLocalRfc6749TokenEndpoint` returns a handle whose shape is pinned here (so the integration and
acceptance tiers cannot invent divergent shapes at execution time):

```ts
interface LocalRfc6749TokenEndpoint {
  tokenEndpoint: string;                         // http://127.0.0.1:<port>/token
  setNextResponse(response: LocalTokenResponse): void; // set the answer for the NEXT request(s), synchronously, between awaited calls
  close(): Promise<void>;                         // afterAll teardown
}

// the closed set of answers a timestep can select — one variant per journey scenario
type LocalTokenResponse =
  | { kind: 'success'; accessToken: string; refreshToken?: string; expiresIn?: number }  // 200; omit refreshToken = no rotation; omit expiresIn = null expiry
  | { kind: 'error'; status: number; error: string; retryAfterSeconds?: number }          // 4xx/5xx JSON error body; retryAfterSeconds sets the Retry-After header (429)
  | { kind: 'malformed'; status: number; body: string }                                   // non-JSON / empty body (drives the defensive-read path)
  | { kind: 'socket-drop' };                                                               // abruptly destroy the socket (transport-error path)
```

- `setNextResponse` mutates a single in-memory field the request handler reads — safe to call
  synchronously between awaited `getTokensFromOidcRefreshClaims` calls, since the server handles one
  request at a time under `--runInBand`.
- the closed `LocalTokenResponse` union is the one contract both tiers import, so a timestep in
  either tier selects a scenario by the same names (`success` / `error` / `malformed` /
  `socket-drop`) — no drift.

### the journey acceptance tier (`getTokensFromOidcRefreshClaims.acceptance.test.ts`)

the repo already wires a full acceptance tier — `jest.acceptance.config.ts`
(`testMatch: **/*.acceptance.test.ts`) run after `npm run build` — but no `*.acceptance.test.ts`
file exists yet. this blueprint adds the first one, because the sdk export IS the contract and
the route mandates contracts carry acceptance coverage. it is a **journey acceptance test**: not
isolated snapshots, but one exhaustive end-to-end flow through the realistic keyrack
`EPHEMERAL_VIA_OAUTH` daily-cron lifecycle (the vision's "day-in-the-life"), across many
timesteps, snapshotted at each checkpoint.

- imports `getTokensFromOidcRefreshClaims` + the three error classes from the **built package
  entrypoint** (blackbox), not from `src/` — to prove the shipped export surface, not an internal
  path
- **the concrete blackbox mechanism (`rule.require.blackbox-via-selflink`)**: add a
  `"simple-oidc-auth": "link:."` self-devDependency to `package.json`, so `node_modules/
  simple-oidc-auth` symlinks to the repo root and resolves to the built `dist/index.js` (the
  `main` entry). the acceptance test imports by the **bare package name**
  (`import { getTokensFromOidcRefreshClaims } from 'simple-oidc-auth'`), which loads `dist/` through
  that self-link — NOT through the `@src/` `moduleNameMapper` (that mapper only rewrites `@src/…`
  specifiers, never the bare package name), and NOT from `src/`. the acceptance runner already
  does `npm run build` first, so `dist/` is fresh. this is why the file must use the package name,
  never the `@src/…` alias the other tiers use — the muscle-memory `@src/…` import is the one
  move that would silently defeat the blackbox purpose, so the blueprint pins the package-name
  import as the required form.
- drives it against `genLocalRfc6749TokenEndpoint` (same local harness, reconfigured per
  timestep), so it needs no external creds and stays hermetic + deterministic
- runs `--runInBand` (per the acceptance test runner) so the single local server port is not raced

**the journey — keyrack's daily silent-refresh lifecycle** (`given [case1] a stored refresh
token from an earlier code-grant login`):

| timestep | scenario | contract outcome (snapshotted) |
|----------|----------|--------------------------------|
| `[t0]` | initial state — a live refresh token held, access token near expiry | precondition holds: token present, no call yet |
| `[t1]` | daily cron wakes, silent refresh, provider does NOT rotate | `{ access: fresh, refresh: null, expiresAt: future }` — caller keeps its refresh |
| `[t2]` | next day, refresh again, provider DOES rotate | `{ access: fresh, refresh: <new>, expiresAt }` — caller persists the new refresh |
| `[t3]` | a stale retry with the OLD (pre-rotation) token | throws `OidcTokenRefreshExpiredError` — single-use rotation observable end-to-end |
| `[t4]` | recover using the NEW refresh token from `[t2]`, and the provider OMITS `expires_in` this cycle | `{ access: fresh, refresh: ..., expiresAt: null }` — the rotated token works AND the explicit "unknown expiry" shape is proven end-to-end (edge) |
| `[t5]` | endpoint hiccups mid-cycle (503) | throws `OidcTokenEndpointMalfunctionError` (💥) — caller must NOT discard the good token |
| `[t6]` | backoff, then retry the SAME good token | `{ access: fresh, ... }` — the good token survived the hiccup (retry recovery) |
| `[t7]` | caller asks for a down-scoped refresh whose scope exceeds the original grant → 400 `invalid_scope` | throws `OidcTokenRequestRejectedError` (✋) — caller narrows the scope claim, does NOT re-auth and does NOT retry as-is |
| `[t8]` | provider rate-limits the caller → 429 `Too Many Requests` with a `Retry-After: 30` header | throws `OidcTokenEndpointMalfunctionError` (💥) with `retryAfterMs: 30000` — caller backs off for the provider-named interval + retries (a 429 is transient, NOT a request to fix) |
| `[t9]` | end of life — provider revokes the refresh (`invalid_grant`) | throws `OidcTokenRefreshExpiredError` (✋) — caller routes the human to re-auth |

**final-state verification**: the journey ends having exercised **all three** load-bearing error
families in one realistic arc — Malfunction/retry (`[t5]` 503, `[t8]` 429), Rejected/fix-request
(`[t7]` invalid_scope), and Expired/re-auth (`[t3]` stale, `[t9]` revoked) — plus keep-vs-rotate
(`[t1]`/`[t2]`) and retry-recovery (`[t5]→[t6]`). each of the four discrimination outcomes is
distinguished by thrown type alone. this is the "day-in-the-life" made executable: a caller that
follows the obvious moves never discards a live token on a hiccup or a rate-limit, never loops on a
dead one, and narrows (not re-auths) on a bad request. each timestep reconfigures
`genLocalRfc6749TokenEndpoint` to answer the scenario, and each `then` snapshots the return value or
the thrown error at that checkpoint.

**the acceptance bar is one representative trigger per error FAMILY, not per trigger** (a
deliberate call, flagged rather than left implicit): the discrimination guarantee is "a caller
tells the three families apart", so the journey snapshots one trigger per family at the blackbox
tier — `invalid_scope` for Rejected, `503`+`429` for Malfunction, `invalid_grant` for Expired.
the OTHER triggers of the same families — `invalid_client` (usecase.5), a raw socket-drop, and a
malformed-2xx body (missing `access_token`) — are proven exhaustively at the **unit + integration
tiers** (matrix A / coverage-by-case), not re-proven at acceptance. rationale: the acceptance
snapshot exists to lock the *consumer-visible contract per family*; a second trigger of an
already-snapshotted family adds a near-duplicate snapshot without a new consumer-visible shape.
if the wisher wants every trigger snapshotted at the blackbox tier, that is a clean add (more
timesteps), flagged here for a conscious decision.

## intrinsic non-idempotency (declared, per rule.require.idempotent-operations)

`getTokensFromOidcRefreshClaims` is **intrinsically non-idempotent** on a provider that rotates — a
successful call spends the input refresh token single-use and the provider commits a NEW one
(`[t2]`→`[t3]` proves it). this is inherent to the rfc-6749 §6 rotation contract, NOT a defect
to design away, so it is named + recorded here rather than made falsely idempotent:

- **the hazard**: if the transport drops AFTER the provider commits the rotation but BEFORE the
  response reaches us, the leaf's transport-catch throws `OidcTokenEndpointMalfunctionError`
  (retry) — yet a same-token retry then correctly surfaces `OidcTokenRefreshExpiredError`
  (re-auth), because the old token is already spent. the extra hop is the CORRECT terminal
  outcome, not a bug: the caller re-auths, which is exactly right for a rotation it cannot
  confirm landed.
- **the caller contract**: on `OidcTokenEndpointMalfunctionError`, a rotation-aware caller
  (keyrack) must treat the input refresh token as *possibly spent* and be ready for the retry to
  land on `Expired` → re-auth. this is documented so an implementor/caller does not mistake the
  extra hop for a defect and "fix" it into a silent-success assumption that would strand a spent
  token.
- **why not made idempotent**: idempotency would require the provider to de-dupe on a
  client-supplied key; rfc-6749 §6 defines no such key for the refresh grant, so the operation
  cannot be recast as findsert/upsert. the non-idempotency is a property of the external
  contract, isolated here at the single i/o leaf.

## technical assumptions to verify at execution

surfaced by the assumptions self-review — each MUST be confirmed before/at execution, not
taken on faith:

- **axios wire serialization** — the code-grant leaf passes `data: { ...object }` with a
  `content-type: application/x-www-form-urlencoded` header (prod [3]). axios does NOT auto-encode
  a plain object to form-urlencoded by default. we mirror the proven-in-prod idiom, but the
  **local integration endpoint parses the raw body** — so it will reveal whether the wire is
  urlencoded or json, and the test asserts the provider receives `grant_type`/`refresh_token`
  correctly. if the raw object idiom does not produce the expected wire, switch to
  `URLSearchParams` in the new leaf (the code grant works today, so this is a confirm, not a
  presumed defect).
- **iso-time duration API** — `asExpiresAt` assumes `addDuration(now(), { seconds })` +
  `IsoTimeStamp` exist with a `{ seconds }` duration shape. per `rule.require.read-package-docs-
  before-use`, read the `iso-time` readme first (`rhx get.package.docs readme --of iso-time`)
  to confirm the exact export names + duration shape before writing the transformer.
- **axios transport-error throw** — with `validateStatus: () => true`, axios resolves all http
  status codes but still **rejects on transport errors** (ECONNREFUSED / timeout). the
  communicator's try/catch relies on this to map transport failures →
  `OidcTokenEndpointMalfunctionError`. the socket-drop integration case proves it.
