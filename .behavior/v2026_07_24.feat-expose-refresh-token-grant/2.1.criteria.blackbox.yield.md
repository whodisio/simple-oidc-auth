# 2.1.criteria.blackbox — getTokensFromOidcRefreshClaims

blackbox criteria for the wish (`0.wish.md`) + vision (`1.vision.yield.md`). experience
boundaries only — the `getTokensFromOidcRefreshClaims` input→output contract as a caller
observes it. no mechanism, no implementation.

the contract under test:

```ts
getTokensFromOidcRefreshClaims(input: {
  claims: {
    token: { refresh: string };
    scope: string[] | null;
    resource: string | null;
  };
  provider: { tokenEndpoint: string };
  operator: { oidcClientId: string; oidcClientSecret: string };
}): Promise<{
  access: string;
  refresh: string | null;
  expiresAt: IsoTimeStamp | null;
}>
```

three typed failure classes a caller can discriminate:
- `OidcTokenRefreshExpiredError` (re-auth) · `OidcTokenRequestRejectedError` (fix request) ·
  `OidcTokenEndpointMalfunctionError` (retry)

---

# usecase.1 = silent refresh (happy path, no rotation)

```
given a token endpoint that honors the refresh grant
  and a live refresh token issued to this operator
  and claims.scope = null and claims.resource = null
    when getTokensFromOidcRefreshClaims is called
      then it resolves with result.access as a non-empty string
        sothat the caller has a fresh access token with no human involvement
      then result.refresh is null
        sothat the caller knows no rotation occurred and keeps its current refresh token
      then result.expiresAt is an absolute IsoTimeStamp in the future
        sothat the caller can schedule the next silent refresh before expiry
```

# usecase.2 = silent refresh with rotation

```
given a token endpoint that rotates the refresh token on each use
  and a live refresh token issued to this operator
    when getTokensFromOidcRefreshClaims is called
      then it resolves with result.access as a non-empty string
      then result.refresh is a non-empty string different from the input refresh token
        sothat the caller can persist the new refresh token atomically
      then result.expiresAt is an absolute IsoTimeStamp in the future

given the same rotate-on-use endpoint and the NOW-SPENT prior refresh token
    when getTokensFromOidcRefreshClaims is called again with the old (pre-rotation) token
      then it throws OidcTokenRefreshExpiredError
        sothat rotation single-use semantics are observable end to end
```

# usecase.3 = expired / revoked refresh (re-auth path)

```
given a token endpoint that answers invalid_grant for this refresh token
  and a refresh token that is revoked, expired, or issued to another client
    when getTokensFromOidcRefreshClaims is called
      then it throws OidcTokenRefreshExpiredError
        sothat the caller routes the human back to full login, never loops
      then the thrown error is an instanceof ConstraintError
        sothat the caller-fault (✋) axis is machine-readable
      then the error metadata carries the provider's invalid_grant signal
        sothat a debugger sees the exact cause (revoked vs expired vs wrong-client)
```

# usecase.4 = rejected request — scope exceeds grant (fix-request path)

```
given a token endpoint that answers invalid_scope
  and a live refresh token
  and claims.scope that exceeds the originally-granted scope
    when getTokensFromOidcRefreshClaims is called
      then it throws OidcTokenRequestRejectedError
        sothat the caller reduces its scope claim rather than retry the same request
      then the thrown error is an instanceof ConstraintError
        sothat this caller-fault is distinct from a live-token retry
      then the error is distinguishable from OidcTokenRefreshExpiredError
        sothat the caller does NOT trigger a needless re-auth of a live token
```

# usecase.5 = rejected request — bad operator credentials

```
given a token endpoint that answers invalid_client (typically 401)
  and a live refresh token
  and operator credentials that are wrong
    when getTokensFromOidcRefreshClaims is called
      then it throws OidcTokenRequestRejectedError
        sothat a config error surfaces as fix-the-request, not a dead refresh
      then it is distinguishable from OidcTokenRefreshExpiredError
        sothat the caller fixes creds instead of a forced human re-login
```

# usecase.6 = endpoint malfunction (retry path)

```
given a token endpoint that returns HTTP 503
  and a live refresh token
    when getTokensFromOidcRefreshClaims is called
      then it throws OidcTokenEndpointMalfunctionError
        sothat the caller backs off and retries, never discards a good refresh token
      then the thrown error is an instanceof MalfunctionError
        sothat the server-fault (💥) axis is machine-readable and distinct from caller-fault

given a token endpoint that is unreachable (socket drop / connection refused / timeout)
    when getTokensFromOidcRefreshClaims is called
      then it throws OidcTokenEndpointMalfunctionError
        sothat transport-layer failures are treated as retryable, like 5xx

given a token endpoint that rate-limits the caller with HTTP 429 (Too Many Requests)
  and a live refresh token
    when getTokensFromOidcRefreshClaims is called
      then it throws OidcTokenEndpointMalfunctionError
        sothat a rate-limit is treated as transient + retryable, NOT a request to fix
      then the thrown error is an instanceof MalfunctionError
        sothat a 429 is distinct from the caller-fault OidcTokenRequestRejectedError (a 429 is NOT re-scope/re-cred)

given a token endpoint that returns HTTP 429 with a Retry-After header
    when getTokensFromOidcRefreshClaims is called
      then the thrown OidcTokenEndpointMalfunctionError carries the retry-after interval in its metadata
        sothat the caller backs off for the provider-named interval rather than an immediate retry that re-trips the limit
```

# usecase.7 = expiry representation is an absolute instant

```
given a token endpoint that returns expires_in = 3599 (seconds)
  and a live refresh token
    when getTokensFromOidcRefreshClaims is called
      then result.expiresAt is an IsoTimeStamp, not a bare number of seconds
        sothat the caller schedules against an absolute instant without now()+x math
      then result.expiresAt is approximately now + 3599 seconds
        sothat the absolute instant faithfully reflects the returned lifetime

given a token endpoint whose success response omits expires_in
    when getTokensFromOidcRefreshClaims is called
      then result.expiresAt is null
        sothat the caller sees an explicit "unknown expiry" rather than a silent guess
```

# usecase.8 = reduced scope / audience claims are honored

```
given a token endpoint that honors a reduced scope request
  and a live refresh token
  and claims.scope = a subset of the originally-granted scope
    when getTokensFromOidcRefreshClaims is called
      then it resolves with a fresh access token
        sothat a caller may down-scope a refresh when it wants fewer grains

given a token endpoint that honors resource indicators (rfc-8707)
  and claims.resource = an absolute uri for the target service
    when getTokensFromOidcRefreshClaims is called
      then it resolves with a fresh access token audience-restricted to that resource
        sothat a caller may target a specific audience for the minted token
```

## boundary conditions (exchange-level)

| input boundary | expected experience |
|----------------|---------------------|
| `claims.scope = null` | full originally-granted scope inherited; no scope sent |
| `claims.resource = null` | no audience restriction; no resource sent |
| `claims.scope = []` (empty) | treated as null (no scope reduction) — no empty scope param sent |
| refresh token present, all else valid | happy path (usecase.1) |
| success body without `access_token` | throws (a malformed success is a provider fault, 💥) |
| success body has `refresh_token` == input token | `result.refresh` reflects it as returned (non-null) |

## the discrimination guarantee (the pit of success)

the single most important blackbox property across usecases 3-6: **a caller can tell the
three failure families apart from the thrown type alone**, and each maps to exactly one
recovery:

| thrown type | fault axis | caller's one correct move |
|-------------|-----------|---------------------------|
| `OidcTokenRefreshExpiredError` | ✋ caller | re-auth (send human to login) |
| `OidcTokenRequestRejectedError` | ✋ caller | fix the request (reduce scope / fix creds) |
| `OidcTokenEndpointMalfunctionError` | 💥 server | back off and retry |

a caller that catches the wrong family and takes the wrong recovery (retry a dead token,
or re-auth over a 503) is the exact failure this contract exists to prevent.
