# wish: simple-oidc-auth — expose getTokensFromOidcRefreshClaims (refresh_token grant)

## .what

add a new export `getTokensFromOidcRefreshClaims` that exchanges a refresh token for a
fresh access token via a provider's OAuth 2.0 token endpoint — symmetric with the
extant `getTokensFromOidcResponseClaims` (the code->tokens leg).

## .why

rhachet keyrack's `EPHEMERAL_VIA_OAUTH` feature needs the refresh->access re-mint leg
(the daily silent-refresh path). simple-oidc-auth already owns the token-endpoint +
provider knowledge, so keyrack reuses rather than duplicates it. the refresh grant is
a first-class OAuth-2.0-base primitive that belongs beside the code grant.

## .source (authoritative)

read the upstream issue first — it is the source of truth (handoffs-at-source):

- `whodisio/simple-oidc-auth#13` — full signature, required behaviors, acceptance

## .proposed signature (symmetric with getTokensFromOidcResponseClaims)

```ts
const tokens = await getTokensFromOidcRefreshClaims({
  provider: { tokenEndpoint: getTokenEndpointByOidcIdentityProvider(OidcIdentityProvider.GOOGLE) },
  operator: { oidcClientId, oidcClientSecret },
  refreshToken,
});
// -> { access, refresh?, expiresIn }
```

## .required behaviors (keyrack depends on these)

- token rotation: when the endpoint returns a NEW refresh token, surface it on the
  result (keyrack writes it back atomically)
- failure classification: distinguish `invalid_grant` (refresh dead -> caller must
  re-auth) from transient 5xx / network (retryable)

## .acceptance

- unit + integration tests against a local RFC-6749 token endpoint: happy
  refresh->access, rotation present + absent, invalid_grant, transient 5xx
- release a pinned version; rhachet keyrack then reuses it
