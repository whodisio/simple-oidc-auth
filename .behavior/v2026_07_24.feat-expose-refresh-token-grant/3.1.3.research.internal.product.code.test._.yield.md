## pattern 1 — unit test: `jest.mock('axios')` at the boundary `[REUSE]`

the extant exchange unit test mocks axios and asserts the request shape + the mapped return.

> [1] `src/domain.operations/exchange/exchangeOidcResponseCodeForTokens.test.ts:5-10`
> ```ts
> jest.mock('axios');
> const axiosMock = axios as any as jest.Mock;
> axiosMock.mockReturnValue({
>   status: 200,
>   data: { access_token: '__access_token__', id_token: '__identity_token__' },

> [2] `src/domain.operations/exchange/exchangeOidcResponseCodeForTokens.test.ts:23-41`
> ```ts
>     expect(axiosMock).toHaveBeenCalledWith(
>       expect.objectContaining({
>         method: 'POST',
>         url: '__endpoint__',
>         headers: { 'content-type': 'application/x-www-form-urlencoded' },
>         data: {
>           grant_type: 'authorization_code', ...
>         },
>       }),
>     );
>     expect(axiosMock.mock.calls).toMatchSnapshot();
> ```

**relation to wish**: the new `exchangeRefreshTokenForTokens` gets a twin unit test — mock
axios, assert it POSTs `grant_type: 'refresh_token'` + `refresh_token` (+ scope/resource when
set), and assert the mapped `{ access, refresh, expiresAt }` return.

- `[REUSE]` the `jest.mock('axios')` + `mockReturnValue` idiom ([1]) and the
  `toHaveBeenCalledWith(objectContaining(...))` + snapshot idiom ([2]) for the wire-shape and
  output-mapping unit tests.
- **caveat**: this idiom mocks axios at the boundary — apt for **unit** wire-shape checks,
  but the wish's acceptance demands a **real** local endpoint (see pattern 4). the mock covers
  matrix-B output mapping + matrix-C request-shape; it does NOT prove matrix-A transport-error
  classification (a mock cannot drop a socket).
